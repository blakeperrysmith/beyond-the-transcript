Beyond the transcript

A transcript keeps the words and drops the rest. Two recordings of the same sentence can read identically as text and mean very different things.

This is a small demo, built to show how I think about speech: what the audio carries, how a small model and measured acoustics read it, and what I would check before trusting either. It is a toy, not a product.

    What to compare
    1. Pick a pair. Press Play on A and on B, or let it play, and read what the model and Praat make of each.
    2. Or press Score all clips to run every sample at once and see how often it is correct, incorrect or unsure.
    1. Plan one sentence you will say twice.
    2. Record it once, then tap the delivery you performed. It shows as saved.
    3. Record it again in a different delivery and tap that one. The model then scores both against what you said you did.

    Your recording stays yours. Run it on your device and the audio never leaves this browser tab. On the server it is analysed in memory and discarded.

    How it was built

    The browser sends raw 16-bit audio to a Python (FastAPI) server. The server computes one shared log-mel front end, measures prosody with Praat, and runs the network in tract. The model is trained in PyTorch and exported to ONNX, and a test checks that tract and PyTorch agree to within 1e-3 on the same input.

    The on-device option runs that same ONNX file in the browser with ONNX Runtime Web (WebAssembly). The feature code is a JavaScript port of the Python one, and a test requires the two to agree to 1e-3 on the log-mel features before the model sees them.

    The two readings of the waveform share only the audio. Today the server runs them one after the other, because Praat is not safe to run twice at once, so the total is the sum of the two.

    Fairness: does it work equally well for everyone?

    Accuracy on speakers the model never heard in training. The dot is the accuracy, the line is a 95% interval resampled by speaker, the dashed line is chance. Where two intervals overlap, this data cannot show a difference in either direction. Sex comes from both corpora; age, race and ethnicity come only from CREMA-D's metadata. Demographic labels are used for evaluation only. The app never estimates them.
